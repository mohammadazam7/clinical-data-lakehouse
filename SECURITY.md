# Security and privacy

## No real patient data

This project is developed and tested only on synthetic patients generated by
[Synthea](https://github.com/synthetichealth/synthea). Nothing in this repository, its
issues, its CI logs or its releases may contain real patient data, de-identified or not.
If you run the pipeline on real records, you are responsible for doing so inside an
environment approved for protected health information, under your organisation's
policies and agreements.

## What the de-identification step does and does not promise

The de-identification step removes or generalises the 18 identifiers listed in the HIPAA
Safe Harbor method (45 CFR 164.514(b)(2)). It is a tool, not a compliance determination:
Safe Harbor also requires that the covered entity has no actual knowledge that the
remaining data could identify a person, which no software can check.

## Reporting a vulnerability

Please report security issues privately through GitHub's
[private vulnerability reporting](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability)
on this repository rather than in a public issue. I aim to reply within a week.
